## 1. Что делает коннектор

Модуль соединяет одну базу Odoo с одним или несколькими магазинами WooCommerce.
Магазин — это запись в Odoo (**WooCommerce > Магазины**); каждый другой объект
модуля принадлежит магазину, поэтому товар, клиент или заказ могут
синхронизироваться с несколькими магазинами независимо.

| Направление | Объект | Механизм |
| --- | --- | --- |
| WooCommerce → Odoo | Товары, вариации, атрибуты, цены, изображения | Плановый опрос (60 минут) и вебхуки `product.*` |
| Odoo → WooCommerce | Товары и их основное изображение | Сервис экспорта, см. [раздел 10](#10-экспорт-каталога) |
| Odoo → WooCommerce | Остатки на складе | Плановое действие (устанавливается **выключенным**) и кнопка **Синхронизировать сейчас** |
| WooCommerce → Odoo | Остатки как корректировки запасов | Сервис выгрузки, когда источник запасов — WooCommerce |
| WooCommerce → Odoo | Заказы, клиенты, возвраты | Вебхуки `order.*` и `customer.*` плюс опрос заказов каждые 10 минут; возврат приходит как изменение своего заказа |
| Odoo → WooCommerce | Номера отслеживания | Автоматически при подтверждении исходящей доставки |

Коннектор никогда не обращается к WooCommerce при открытии страницы: каждый
исходящий вызов — это задание очереди, поэтому медленный или недоступный магазин не
блокирует интерфейс Odoo.

## 2. Требования

* **Odoo** 19.0 или 20.0, Community или Enterprise. Модуль зависит от стандартных
  модулей `sale_management`, `stock`, `account`, `delivery` и `mail`.
* **WooCommerce** 3.5 или новее. Модуль тестируется на текущей линейке 11.x
  (11.2.2 во время разработки).
* **HTTPS на стороне магазина.** WooCommerce 11 принимает учётные данные REST
  только через SSL: тот же запрос по обычному HTTP получает ответ `401`. URL
  магазина должен быть доступен через TLS; `http://` принимается только для
  локальных имён `localhost`, `127.0.0.1`, `::1`, `odoo` и `wordpress`.
* **Публичный HTTPS-адрес Odoo**, если нужны вебхуки. Это значение системного
  параметра `web.base.url`; из него строится адрес вебхука.
* **Python**: только библиотека `requests`, входящая в каждую установку Odoo.
  Ничего не нужно ставить через pip, никаких модулей OCA.
* Процесс планировщика Odoo (cron) должен работать (стандартный `odoo-bin`
  работает), иначе очередь никогда не выполняется.

## 3. Установка

1. Скопируйте каталог модуля в один из каталогов дополнений (addons) сервера Odoo:

   ```bash
   cp -R rex_woocommerce_connector /opt/odoo/addons/
   ```

   Каталог модуля должен содержать оба файла — `__init__.py` и `__manifest__.py`;
   Odoo игнорирует путь дополнений, в котором нет такого модуля.

2. Перезапустите Odoo и обновите список приложений:

   **Приложения > Обновить список приложений**, найдите *Two-way Sync for WooCommerce* и
   нажмите **Установить**.

3. При установке создаются:

   * группы доступа **WooCommerce / Пользователь** и **WooCommerce / Менеджер**;
   * семь плановых действий из [раздела 8](#8-плановые-действия-и-ручная-синхронизация);
   * стандартные параметры конфигурации из [раздела 20](#20-параметры-конфигурации).

4. В главном меню появляется приложение **WooCommerce** с пунктами **Магазины**,
   **Задания**, **Журнал активности** и **Доставки вебхуков**.

Больше на сервере ничего не нужно: ни шага сборки, ни дополнительного сервиса, ни
таблицы, которую надо создавать вручную.

### Проверка установки

```text
1. WooCommerce > Магазины > Создать   форма открывается без ошибки
2. Проверить соединение               состояние становится "Подключено"
3. Синхронизировать сейчас             уведомление показывает число заданий
4. WooCommerce > Задания              задания появляются как "В очереди", затем "Готово"
5. WooCommerce > Журнал активности    появляются строки "Imported N products."
```

## 4. Подготовка WooCommerce

### 4.1 Постоянные ссылки и HTTPS

REST API живёт по адресу `/wp-json/`, что работает только с "красивыми"
постоянными ссылками: в **Настройки > Постоянные ссылки** должно быть что угодно,
кроме *Простой*. Магазин также должен работать через HTTPS, как сказано в
[разделе 2](#2-требования).

### 4.2 Ключ REST API

1. В WordPress откройте **WooCommerce > Настройки > Дополнительно > REST API**.
2. Нажмите **Добавить ключ**:
   * Описание: `Odoo` (любое);
   * Пользователь: администратор или менеджер магазина с правами чтения и записи;
   * Права: **Чтение/Запись**.
3. Нажмите **Сгенерировать ключ API** и сразу скопируйте оба значения: ключ
   потребителя (`ck_...`) и секрет потребителя (`cs_...`). Секрет показывается
   только один раз.

Права чтения/записи нужны, потому что коннектор отправляет остатки и заметки
отслеживания и создаёт товары во время экспорта.

### 4.3 Пароль приложения WordPress (только для экспорта изображений)

Изображения товаров загружаются в медиатеку WordPress, а ядро WordPress не
принимает ключ потребителя WooCommerce для этой точки. Если нужно экспортировать
изображения из Odoo, создайте пользователя WordPress с правом *upload_files* и
пароль приложения для него (**Пользователи > Профиль > Пароли приложений**), затем
заполните поля **Пользователь WordPress** и **Пароль приложения WordPress** в
магазине. Без них каталог всё равно экспортируется; пропускается только шаг с
изображением, с предупреждением в журнале активности.

Импорт изображений (WooCommerce → Odoo) не требует дополнительных данных: он
скачивает публичный адрес изображения.

### 4.4 Планировщик WordPress

WooCommerce доставляет вебхуки через псевдо-cron WordPress, который запускается при
посещениях сайта. В магазине с малым трафиком доставка может запаздывать. Коннектор
это учитывает: опрос заказов исправляет всё, что пропустил вебхук, поэтому рабочий
cron WordPress — это улучшение задержки, а не требование.

## 5. Создание магазина в Odoo

**WooCommerce > Магазины > Создать**. Все поля ниже находятся на форме магазина.

| Поле | Значение |
| --- | --- |
| **Название** | Метка, используемая только в Odoo. |
| **URL магазина** | Корневой адрес WordPress, например `https://shop.example.com`. Завершающий слеш и `/wp-json` в конце удаляются; если схемы нет, добавляется `https://`. Обычный `http` принимается только для локальных имён. |
| **Ключ потребителя** / **Секрет потребителя** | Ключ REST API из WooCommerce. Виден только группе *Менеджер*. |
| **Пользователь WordPress** / **Пароль приложения WordPress** | Необязательно; нужно только для экспорта изображений товаров. Только *Менеджер*. |
| **Проверять TLS-сертификат** | Оставьте отмеченным. Снимайте флажок только для локального магазина с самоподписанным сертификатом: тогда учётные данные передаются по непроверенному соединению. |
| **Версия WooCommerce**, **Валюта**, **Цены введены с налогом** | Только чтение, заполняется кнопкой **Проверить соединение**. |
| **Склад** | Источник отправляемого остатка и назначение выгружаемого остатка. По умолчанию — первый склад компании; если поле пустое, коннектор использует этот же склад. |
| **Прайс-лист** | Применяется к импортированным заказам. |
| **Категория товаров по умолчанию** | Категория товаров, созданных из WooCommerce. Если пустая — первая категория товаров в базе. |
| **Товар для доставки** | Товар для строк доставки в импортированных заказах. Если пустой, коннектор находит или создаёт услугу с внутренним кодом `WOO-SHIPPING`. |
| **Товар для доплат** | Товар для строк доплат (fee) в импортированных заказах. Если пустой — услуга с кодом `WOO-FEE`. |
| **Источник запасов** | `Odoo`, `WooCommerce` или `Выключено`. См. [раздел 11](#11-синхронизация-запасов). |
| **Тип количества** | `Доступно (на складе минус зарезервировано)` (по умолчанию) или `На складе`. *Доступно* — безопасный выбор: запас, зарезервированный под подтверждённые заказы, уже продан, и повторная публикация привела бы к перепродаже. |
| **Импортировать товары из WooCommerce** | Управляет опросом товаров и товарной частью **Синхронизировать сейчас**. Вебхуки `product.*` обрабатываются для каждого активного магазина. |
| **Экспортировать товары в WooCommerce** | Управляет плановым действием экспорта. Также не даёт последующему импорту перезаписать цену продажи Odoo ценой WooCommerce (первый импорт всегда приносит цену). |
| **Синхронизировать заказы** | Управляет опросом заказов и **Синхронизировать сейчас**; вебхуки `order.*` обрабатываются для каждого активного магазина. |
| **Синхронизировать клиентов** | Управляет плановым действием импорта клиентов; вебхуки `customer.*` обрабатываются для каждого активного магазина. |
| **Синхронизировать возвраты** | Импортирует возвраты WooCommerce как кредит-ноты, как только по заказу продажи выставлен счёт. См. [раздел 14](#14-возвраты-средств). |
| **Отправлять номера отслеживания в WooCommerce** | Включает отправку данных исполнения. |
| **Подтверждать импортированные заказы** | Отмечено: импортированные заказы подтверждаются. Снято: остаются коммерческими предложениями. |
| **Создавать отсутствующие товары** | Отмечено: товар из заказа, который не удалось сопоставить, создаётся как минимальный товар. Снято: импорт заказа завершается понятной ошибкой. |
| **Допуск по итоговой сумме** | Допустимая разница между суммой Odoo и суммой WooCommerce, по умолчанию `0.02`. Большая разница записывается как предупреждение. |
| **Максимум попыток задания** | Количество попыток до окончательного отказа задания, по умолчанию `5`. |
| **URL вебхука** | Вычисляется из `web.base.url`; можно скопировать. |
| **Секрет вебхука** | Случайный секрет, созданный вместе с магазином; используется для проверки заголовка `X-WC-Webhook-Signature`. Только *Менеджер*. |
| **Зарегистрированные вебхуки** | JSON-сводка последнего запуска **Зарегистрировать вебхуки**. |
| **Последняя синхронизация товаров**, **заказов**, **Последний экспорт товаров** | Водяные знаки (UTC), записываемые после успешного запуска. Опрос, в котором запись не удалась по причине, которая может исчезнуть (сеть, блокировка), сохраняет старый водяной знак, поэтому следующий опрос повторяет попытку; отказ, который не изменится (другая валюта, несопоставленный товар при выключенном создании товаров), журналируется и не задерживает водяной знак. |
| **Задания в очереди**, **Задания с ошибкой**, **Последняя ошибка** | Показаны в списке и на форме. |

**URL магазина фиксируется**, как только синхронизирована первая запись: он является
частью идентичности каждой строки соответствия, поэтому изменение вызывает ошибку.
Если магазин действительно переехал, создайте новую запись магазина.

## 6. Проверка соединения

Нажмите **Проверить соединение**. Кнопка:

1. вызывает `GET /wp-json/wc/v3/system_status` с сохранёнными учётными данными;
2. читает версию WordPress, версию WooCommerce и валюту магазина;
3. активирует валюту в Odoo, если она существует, но архивирована;
4. читает `GET /wp-json/wc/v3/settings/tax/woocommerce_prices_include_tax` и
   сохраняет признак *Цены введены с налогом*;
5. записывает состояние **Подключено**, версию WooCommerce, дату и очищает **Последнюю ошибку**.

При ошибке магазин помечается как **Ошибка**, сообщение сохраняется в **Последней
ошибке** и возникает `UserError`, чтобы причина была видна сразу. Две типичные
причины — неверный ключ и магазин без HTTPS (см.
[раздел 23](#23-устранение-неисправностей)).

`prices_include_tax` используется тогда, когда экспорт каталога записывает цену
обратно в WooCommerce (отправляется цена с налогом). Строки заказов пересчитывать не
нужно: WooCommerce передаёт их без налога в каждом магазине (см.
[раздел 12](#12-заказы)).

## 7. Вебхуки

Нажмите **Зарегистрировать вебхуки** после успешной проверки соединения.

* Предусловие: `web.base.url` должен быть **публичным HTTPS-адресом** Odoo. Кнопка
  отказывается работать, если вычисленный адрес вебхука не `https://`, потому что
  WordPress передавал бы данные заказов открытым текстом или не передавал бы вовсе.
* Точка входа: `https://<ваш odoo>/woocommerce/webhook/<id магазина>`.
* Регистрируются темы: `order.created`, `order.updated`, `order.deleted`,
  `product.created`, `product.updated`, `product.deleted`, `customer.created`,
  `customer.updated`. В WooCommerce нет темы для возвратов: возврат изменяет свой
  заказ и приходит как `order.updated`.
* Каждый вебхук называется `Odoo <тема>` и несёт **секрет вебхука** магазина.
  Кнопка сохраняет JSON-сводку в **Зарегистрированных вебхуках**.
* Повторное нажатие кнопки создаёт только те темы, которых для этого адреса ещё
  нет; существующие вебхуки сохраняются.

Как обрабатывается доставка:

1. Точка входа проверяет подпись HMAC-SHA256 **сырого тела** по заголовку
   `X-WC-Webhook-Signature` (сравнение постоянного времени) и отвечает `401`, если
   подпись не совпадает.
2. Доставки дедуплицируются по `X-WC-Webhook-Delivery-ID`; повторная отвечает
   `200` и ничего не делает. (`X-WC-Webhook-ID` — это id самого вебхука, он
   одинаков для каждой доставки, поэтому не может идентифицировать отдельное
   событие.)
3. Неподписанная проверка `webhook_id=<id>`, которую WooCommerce отправляет при
   создании или сохранении вебхука, и пустое тело получают ответ `200` и дальше
   не обрабатываются.
4. Данные сохраняются в **Доставках вебхуков**, задание типа *Обработать вебхук*
   ставится в очередь с высшим приоритетом, и точка входа немедленно отвечает
   `200`. Сам импорт выполняется в очереди.

Поскольку доставка подтверждается до импорта, медленный Odoo никогда не заставляет
WordPress повторять попытку. Если что-то не удалось, задание видно в **Заданиях** и
в **Журнале активности**.

## 8. Плановые действия и ручная синхронизация

Модуль устанавливает семь плановых действий (**Настройки > Технические >
Автоматизация > Плановые действия**, фильтр *WooCommerce*):

| Название | Интервал | Активно после установки | Что делает |
| --- | --- | --- | --- |
| WooCommerce: process the synchronisation queue | 1 минута | да | Берёт и выполняет до 20 заданий очереди (`rex_woocommerce_connector.queue_batch`). |
| WooCommerce: poll orders | 10 минут | да | Ставит опрос `order_import` для каждого активного магазина с *Синхронизировать заказы*. |
| WooCommerce: poll products | 60 минут | да | Ставит опрос `product_import` для каждого активного магазина, импортирующего товары. |
| WooCommerce: push stock | 30 минут | **нет** | Ставит `stock_push` для магазинов, где источник запасов — Odoo. |
| WooCommerce: export products | 30 минут | **нет** | Ставит `product_export` для магазинов, экспортирующих товары. |
| WooCommerce: pull stock | 15 минут | **нет** | Ставит `stock_pull` для магазинов, где источник запасов — WooCommerce. |
| WooCommerce: import customers | 120 минут | **нет** | Ставит `customer_import` для магазинов с *Синхронизировать клиентов*. |

Четыре действия — **push stock**, **export products**, **pull stock** и **import
customers** — устанавливаются **выключенными**: каждое из них пишет в живую систему
или читает целую таблицу, поэтому включаются осознанным решением.

Кнопки на форме магазина ставят работу в очередь немедленно и сразу возвращают
управление; уведомление говорит, что именно поставлено в очередь, а дальше работает
очередь:

* **Синхронизировать сейчас** — опрос заказов, если отмечено *Синхронизировать
  заказы*; опрос товаров, если отмечено *Импортировать товары*; и полная отправка
  остатков, если источник запасов — **Odoo**;
* **Экспортировать товары** — задание `product_export`;
* **Импортировать клиентов** — задание `customer_import`.

## 9. Импорт каталога

Опрос товаров читает `GET /wp-json/wc/v3/products` в порядке id, импортирует каждый
товар и затем вариации каждого вариативного товара. Опрос отправляет
`modified_after` с водяным знаком *Последняя синхронизация товаров* и
`dates_are_gmt=true` (без него WooCommerce сравнивает дату с местным временем
сайта), поэтому после первого запуска читаются только товары, изменённые с момента предыдущего успешного
опроса. Первый запуск читает весь каталог — это то, что нужно на пустой базе, и то,
что на большом каталоге стоит планировать вне рабочих часов.

Для каждого товара коннектор создаёт или обновляет один `product.template`:

| Поле Odoo | Источник |
| --- | --- |
| Название | Название WooCommerce (HTML-сущности раскодированы) |
| Внутренний код | SKU; также используется один раз, чтобы принять существующий товар Odoo с таким же кодом |
| Штрихкод | Штрихкод WooCommerce |
| Цена продажи | Цена WooCommerce при первом импорте; в дальнейшем **только когда "Экспортировать товары в WooCommerce" снято**, иначе побеждает цена Odoo и не перезаписывается |
| Тип | `Товар` (расходный или запасной), с признаком *Отслеживать запасы*, когда WooCommerce управляет остатками |
| Категория | *Категория товаров по умолчанию* магазина, иначе первая категория товаров |
| Описание для продажи | Краткое и полное описание, теги удалены, до 4000 символов |
| Вес | Вес WooCommerce |
| Изображение | **Первое** изображение товара, скачанное по публичному адресу (изображения больше 10 МБ пропускаются) |
| Атрибуты | Каждый атрибут со своими значениями становится `product.attribute` (создаёт вариации) со значениями |
| Вариации | Сопоставляются по комбинации атрибутов в шаблоне; обновляется их SKU. Их цена сохраняется как дополнительная цена значения атрибута (при первом импорте и при каждом импорте, когда экспорт выключен). Odoo может задать отдельные цены вариаций только для товаров с **одним** изменяемым атрибутом; если таких атрибутов несколько, цены вариаций не меняются, а в журнал записывается предупреждение |

Правила сопоставления, по порядку:

1. строка соответствия для этого магазина и этого id WooCommerce — обычный случай;
2. SKU — только чтобы принять товар, ещё не сопоставленный с этим магазином;
3. иначе создаётся новый товар.

Товар, который не удалось сопоставить или записать, журналируется, и импорт
переходит к следующему: один сломанный товар никогда не останавливает опрос.
Несопоставленные вариации записываются как предупреждения; коннектор не создаёт
вариации в Odoo.

Удаление товара в WooCommerce **архивирует** сопоставленный товар Odoo
(`active = false`) через вебхук `product.deleted`; в Odoo ничего никогда не
удаляется. Архивированный товар исчезает из обычного поиска, но сохраняет историю
продаж, и строка уровня info в журнале активности фиксирует архивирование.

## 10. Экспорт каталога

Сервис экспорта отправляет в WooCommerce **товары** (не услуги) компании магазина,
которые **продаются в Odoo**: название, внутренний код как SKU, цену продажи как
`regular_price`, описание для продажи, штрихкод и статус `publish`, после чего
загружает основное изображение через медиатеку WordPress, если в магазине
настроены пользователь WordPress и пароль приложения. Изображение, которое не
изменилось с последней загрузки, повторно не загружается.

Что именно записывается, определяет владелец товара:

* товары, **созданные в Odoo** (или принятые по SKU при первом экспорте),
  принадлежат Odoo и обновляются при каждом экспорте;
* товары, **импортированные из WooCommerce**, принадлежат магазину, и экспорт
  никогда их не переписывает, поэтому их HTML-описание, галерея и обычная и
  акционная цены остаются такими, как их задал продавец;
* сгенерированные товары `WOO-SHIPPING` и `WOO-FEE`, а также любые услуги никогда
  не экспортируются.

Экспорт запускается кнопкой **Экспортировать товары** на форме магазина (все
подходящие товары) или плановым действием *WooCommerce: export products*, которое
устанавливается **выключенным** (30 минут) и экспортирует товары, изменённые после
его предыдущего запуска.

Перед созданием товара экспорт ищет в WooCommerce товар с таким же SKU и
**принимает** его вместо создания дубликата, поэтому первый экспорт существующего
каталога привязывает товары Odoo к товарам WooCommerce, которые уже несут их
внутренний код.

Что важно для учёта:

* экспорт всегда записывает **простой** товар; вариации не экспортируются;
* отправляется **цена продажи** Odoo, а не цена из прайс-листа;
* экспорт никогда не удаляет товар в WooCommerce;
* шаг с изображением пропускается с предупреждением в журнале активности, если
  учётные данные WordPress отсутствуют или загрузка не удалась.

## 11. Синхронизация запасов

Направление определяет **Источник запасов**:

| Значение | Отправка (Odoo → WooCommerce) | Выгрузка (WooCommerce → Odoo) |
| --- | --- | --- |
| `Odoo` | Включено; запускается плановым действием и кнопкой **Синхронизировать сейчас** | Выключено |
| `WooCommerce` | Выключено | Включено, когда поставлено задание выгрузки |
| `Выключено` | Выключено | Выключено |

**Отправка.** Для каждого сопоставленного товара магазина коннектор вычисляет
количество на складе магазина (локация `WH/Stock` и её дочерние) — либо фактический
остаток, либо доступное количество, в зависимости от **Типа количества** — и
отправляет `manage_stock: true` вместе с `stock_quantity`:

* простой товар: `PUT /wp-json/wc/v3/products/<id>`;
* вариация: `PUT /wp-json/wc/v3/products/<id родителя>/variations/<id>`.

Отправляются только **запасные** товары: расходный товар или услуга не имеют
остатков в Odoo, поэтому публиковать нечего. Родительский вариативный товар
пропускается в обоих направлениях: остаток несут его вариации. Отрицательное
доступное количество отправляется как `0`. Товар, который не удался,
журналируется, и отправка продолжается. На каждый товар берётся рекомендательная
блокировка PostgreSQL, поэтому два параллельных задания не могут перезаписать друг
друга устаревшим значением.

Плановое действие отправки остатков **выключено** после установки модуля, чтобы
свежая установка никогда не записала количества в живой магазин до того, как
кто-то проверил склад и соответствия. Включите его, когда будете готовы.

**Выгрузка.** Когда источник запасов — WooCommerce, выгрузка читает
`stock_quantity` каждого сопоставленного товара — из точки вариаций, если
соответствие указывает на вариацию — и создаёт подтверждённую **корректировку
запасов** в локации склада магазина, поэтому движение прослеживаемо и оценено, когда
включена автоматическая оценка. Она запускается плановым действием *WooCommerce: pull
stock*, установленным **выключенным** (15 минут), или вручную поставленным заданием
`stock_pull`.

## 12. Заказы

Заказы приходят двумя путями:

* **вебхуки** — `order.created`, `order.updated`, `order.deleted`, обрабатываются
  очередью в течение минуты;
* **опрос** — каждые 10 минут `GET /wp-json/wc/v3/orders` с
  `modified_after=<последняя синхронизация заказов>`, `dates_are_gmt=true` и
  `orderby=id&order=asc` для
  каждого активного магазина с *Синхронизировать заказы*.

Оба пути ведут к одному и тому же идемпотентному импорту, поэтому вебхук и опрос
могут "гонять" без дублирования: в таблице соответствий есть уникальное ограничение
на (магазин, id WooCommerce).

Импортированный заказ становится `sale.order`:

| Поле Odoo | Источник |
| --- | --- |
| Клиент | см. [раздел 13](#13-клиенты) |
| Дата заказа | `date_created_gmt` (naive UTC), иначе текущее время |
| Ссылка клиента | Номер заказа WooCommerce |
| Документ-источник | `WooCommerce #<номер>` |
| Прайс-лист | *Прайс-лист* магазина, если задан |
| Внутренняя заметка | Заметка клиента, название способа оплаты и ссылка на заказ WooCommerce |
| Строки | см. ниже |
| Статус | подтверждён, если отмечено *Подтверждать импортированные заказы*, иначе коммерческое предложение |

Обработка строк:

* **строка товара**: количество из `quantity`, цена за единицу
  `subtotal / quantity` и процент скидки, вычисленный из
  `(subtotal - total) / subtotal` — именно так сохраняется купон, уменьшающий
  строку;
* **строка доставки**: **Товар для доставки** магазина, количество 1, цена из
  `shipping_lines[].total`;
* **строка доплаты**: **Товар для доплат** магазина, иначе услуга с внутренним кодом
  `WOO-FEE`, количество 1, цена из `fee_lines[].total`;
* **налоги**: каждый налог строки WooCommerce сопоставляется через карту налогов
  магазина. Налоги сопоставляются **по ставке** с налогами продажи компании
  магазина, с предпочтением налога со счётом, а затем стандартного налога продажи
  компании. Строка, налог которой не имеет соответствия в Odoo, импортируется без
  этого налога.

WooCommerce передаёт промежуточные и итоговые суммы строк заказа **без налога** в
каждом магазине, в том числе в магазинах, где цены введены с налогом, поэтому суммы
строк используются как цены без налога, а Odoo добавляет сопоставленные налоги.
Сопоставляются только те налоги Odoo, которые *не* включены в цену. *Цены введены с
налогом* имеет значение тогда, когда экспорт каталога записывает цену обратно в
WooCommerce. В магазине с ценами, введёнными с налогом, заказ может отличаться от
WooCommerce на одну копейку, потому что WooCommerce округляет цену с налогом.

После создания заказа коннектор сравнивает сумму Odoo с суммой WooCommerce
(`total`). Разница больше **Допуска по итоговой сумме** записывается в журнал
активности как предупреждение (`Order SO…: Odoo total … differs from WooCommerce
total …`), а не принимается молча. Обычные причины — отсутствующая в Odoo ставка
налога, сложная (compound) ставка, округление на одну копейку в магазине с ценами,
введёнными с налогом, или купон, уменьшивший доставку или доплаты.

Изменение статуса уже импортированного заказа **не** переписывает заказ продажи:
обновляются собственные поля коннектора (статус WooCommerce, признак оплаты, сумма).
Исключение — `cancelled` и вебхук `order.deleted`, которые отменяют заказ продажи,
если он ещё не выполнен и не отменён. Есть и обратное направление: отмена заказа
продажи в Odoo ставит задание статуса, которое переводит заказ WooCommerce в
`cancelled`, если существует соответствие.

Когда отмечено *Создавать отсутствующие товары*, а строка заказа не имеет ни
соответствия, ни совпадения по SKU, коннектор создаёт минимальный товар **и сразу
ставит его в соответствие**, поэтому более поздний экспорт каталога не создаст
вторую копию того же товара в WooCommerce.

Валюта: заказ в валюте, отличной от валюты магазина, отклоняется с ошибкой в
журнале активности; мультивалютные заказы в версии 1.0 не поддерживаются.

Купоны: строки `coupon_lines` как таковые не импортируются. Скидка в процентах или
фиксированная скидка, уменьшающая итог строки, отражается в скидке строки; купон,
уменьшающий доставку или доплаты, делает сумму Odoo отличной, и это фиксируется
проверкой суммы.

## 13. Клиенты

Клиент сопоставляется в таком порядке:

1. строка соответствия для этого магазина и этого id клиента WooCommerce;
2. существующий партнёр Odoo с тем же адресом электронной почты (без учёта
   регистра);
3. новый `res.partner`.

При создании партнёр получает имя, e-mail, телефон и платёжный адрес (улица,
улица 2, город, индекс, страна, область) и признак клиента. У существующего партнёра
платёжный адрес заполняет только **пустые** поля — Odoo никогда не перезаписывает
адрес, который кто-то ввёл.

Гостевой заказ (`customer_id` 0) поддерживается: партнёр находится по платёжному
e-mail или создаётся, но **строка соответствия не создаётся**, поэтому более поздний
настоящий клиент с тем же e-mail не будет молча присоединён к гостевой записи.

Клиенты также создаются неявно во время импорта заказов, и это обычный путь:
коннектор читает `GET /wp-json/wc/v3/customers/<id>` и, если клиента прочитать не
удалось, использует блок платёжных данных заказа. Вебхуки `customer.created` и
`customer.updated` импортируют клиента без заказа. Массовый импорт доступен кнопкой
**Импортировать клиентов** и плановым действием *WooCommerce: import customers*
(устанавливается выключенным, каждые 120 минут); оба ставят задание
`customer_import`, которое читает весь список клиентов.

Адрес доставки заказа в версии 1.0 не создаётся как дочерний контакт;
синхронизируется платёжный адрес клиента. Это указано в
[разделе 22](#22-известные-ограничения-версии-10).

## 14. Возвраты средств

В WooCommerce нет вебхука для возвратов: возврат изменяет свой заказ. Каждый раз,
когда заказ читается — 10-минутным опросом или вебхуком `order.updated` — и
содержит возврат без кредит-ноты, в очередь ставится задание *Импортировать
возврат*. Это задание читает каждый возврат заказа и создаёт одну **кредит-ноту
клиенту** (`out_refund`) на каждый возврат WooCommerce. Для заказа, по которому ещё
не выставлен счёт, ничего в очередь не ставится; его возвраты будут подхвачены при
следующем изменении заказа после выставления счёта.

Предусловия:

* заказ импортирован (иначе возврат журналируется и пропускается);
* заказ продажи имеет **проведённый счёт** (заказ без счёта журналируется как
  предупреждение и пропускается).

Как строится кредит-нота:

* **возврат со строками**: каждая строка кредитуется своим количеством по
  `total / quantity` (без налога), с налогами соответствующей строки счёта (или
  налогами продажи товара, если строка счёта не найдена); вариация сопоставляется
  по своему id вариации. Когда сумма возврата включает доставку или доплаты,
  разница добавляется одной строкой без налога, поэтому сумма кредит-ноты всегда
  равна сумме возврата;
* **возврат только суммы** (ручной возврат в админке WooCommerce, без строк): одна
  строка с суммой возврата и **без налога**. Коннектор кредитует ровно то, что
  клиент получил обратно; налоговая часть такого возврата **не** сторнируется.
  Журнал активности фиксирует созданную кредит-ноту, поэтому бухгалтер может её
  скорректировать. Это осознанное поведение версии 1.0, задокументированное, чтобы
  его не обнаружили во время аудита;
* кредит-нота проводится сразу, с журналом и валютой счёта;
* ссылка — `WooCommerce refund <id возврата>`, и она проверяется перед созданием,
  поэтому один и тот же возврат никогда не создаст вторую кредит-ноту; возврат,
  который не удалось провести, не оставляет после себя черновика.

Импорт возвратов ничего не возвращает на склад, а оплата и бухгалтерское
сопоставление возврата не автоматизируются.

## 15. Номера отслеживания

Когда в Odoo подтверждается **исходящая** доставка, коннектор ставит задание
`fulfilment_push`. Задание читает номер отслеживания доставки
(`carrier_tracking_ref`) и добавляет **заметку клиенту** к заказу WooCommerce:

```text
Shipment WH/OUT/00012 with DHL. Tracking number: 1234567890
```

Название перевозчика добавляется, если у доставки есть перевозчик, а часть с
номером отслеживания пропускается, если номер пуст. Заметка видна клиенту на
странице заказа WooCommerce и в письмах "заметка к заказу".

Требования: отмечено *Отправлять номера отслеживания в WooCommerce*, исходящая
доставка связана с заказом продажи, и существует соответствие между этим заказом и
магазином. Ошибка никогда не блокирует доставку: она перехватывается,
журналируется и остаётся в очереди, а доставка остаётся подтверждённой.

Если в одной базе несколько магазинов, обработчик доставки ставит задание для первого
активного магазина с включённым *Отправлять номера отслеживания*; дальше задание
находит соответствие заказа для этого магазина. Если тот же заказ существует в
нескольких магазинах, заметка уйдёт в магазин, который выбрал обработчик. Это
ограничение версии 1.0.

## 16. Очередь заданий

Каждый шаг синхронизации — это строка `woo.job`. Экран очереди (**WooCommerce >
Задания**) показывает название, магазин, тип, состояние, число попыток, следующий
запуск, время завершения и длительность, позволяет поиск и группировку по
состоянию, типу и магазину.

Состояния:

| Состояние | Значение |
| --- | --- |
| В очереди | Ждёт своей очереди; после ошибки `Следующий запуск` в будущем |
| Выполняется | Взято работником; после истечения аренды возвращается в очередь |
| Готово | Завершено успешно |
| Ошибка | Окончательно отклонено после *Максимума попыток задания* |
| Отменено | Отменено вручную |

Выполнение:

* плановое действие очереди работает **каждую минуту** и берёт до
  `rex_woocommerce_connector.queue_batch` заданий (по умолчанию 20) через
  `FOR UPDATE SKIP LOCKED`, поэтому несколько работников Odoo никогда не выполняют
  одно и то же задание;
* задание, находящееся в состоянии **Выполняется** дольше
  `rex_woocommerce_connector.job_lease_minutes` (по умолчанию 30), считается погибшим и
  возвращается в **В очереди**, поэтому упавший работник не блокирует очередь;
* падающее задание повторяется с экспоненциальной задержкой от 5 секунд до
  5 минут, пока не достигнет *Максимума попыток задания* (поле магазина, по
  умолчанию 5), после чего отклоняется окончательно;
* каждая попытка сохраняется с ошибкой в **Последней ошибке**, а исключение
  записывается в журнал активности с HTTP-статусом и кодом ошибки WooCommerce.

Ручные действия на форме задания: **Повторить** (ошибка или отменено → в очереди,
счётчик попыток сбрасывается), **Отменить** (в очереди или ошибка → отменено),
**Выполнить сейчас** (выполняет задание из очереди немедленно в текущей транзакции).

Вкладка **Payload** показывает JSON, с которым создано задание, а **Последняя
ошибка** — исключение последней попытки.

## 17. Журнал активности

**WooCommerce > Журнал активности** — операционная история коннектора. В интерфейсе
он доступен только для чтения.

| Уровень | Когда пишется |
| --- | --- |
| Info | Пакет завершён: "Imported N products.", "Pushed stock for N products.", создана кредит-нота, отправлена заметка отслеживания |
| Warning | Не удалось обработать товар, изображение или вариацию; сумма заказа отличается; возврат пропущен |
| Error | Задание упало: сообщение исключения, HTTP-статус, код ошибки WooCommerce и фрагмент payload |

Каждая строка хранит дату, магазин, уровень, сообщение, HTTP-статус, код ошибки
WooCommerce, URL, задание, запись Odoo и payload (до 20 000 символов). Доступны
фильтры **Ошибки** и **Предупреждения** и группировка по уровню и магазину.

Упавшее задание всегда создаёт ровно одну строку ошибки, поэтому "что сломалось и
почему" становится понятно без чтения серверного лога.

## 18. Доставки вебхуков

**WooCommerce > Доставки вебхуков** хранит каждую принятую доставку: дату, магазин,
тему, id ресурса WooCommerce, ключ дедупликации (`X-WC-Webhook-Delivery-ID`), состояние
(*В очереди* → *Готово*), дату обработки и сырой payload. Доставка, задание которой
упало, остаётся в **В очереди** — причина в **Последней ошибке** созданного ею
задания.

Используйте этот экран, чтобы ответить на два вопроса: *доставил ли WordPress?* и
*обработана ли доставка?* Доставка в состоянии **В очереди**, задание которой ещё
ожидает, — это нормально на несколько секунд; доставка, застрявшая в **В очереди**,
означает, что плановое действие очереди не работает.

## 19. Права доступа

| Группа | Права |
| --- | --- |
| WooCommerce / Пользователь | Читает магазины, задания, журнал активности, доставки вебхуков и таблицы соответствий. Кнопки на форме магазина записывают в запись магазина, поэтому воспользоваться ими может только участник группы *Менеджер*. |
| WooCommerce / Менеджер | Полное создание, редактирование и удаление объектов коннектора; видит ключ потребителя, секрет потребителя, секрет вебхука и учётные данные WordPress. |

Только группа *Менеджер* видит учётные данные, с помощью которых можно читать или
изменять магазин, — именно поэтому групп две.

## 20. Параметры конфигурации

Установщик записывает эти значения по умолчанию в **Настройки > Технические >
Параметры > Системные параметры**. В версии 1.0 код читает первые два; остальные
записываются установщиком и зарезервированы для следующих версий:

| Параметр | По умолчанию | Читается в 1.0 | Значение |
| --- | --- | --- | --- |
| `rex_woocommerce_connector.queue_batch` | 20 | да | Сколько заданий выполняет один запуск очереди. |
| `rex_woocommerce_connector.job_lease_minutes` | 30 | да | Сколько задание может находиться в состоянии *Выполняется* до возврата в очередь. |
| `rex_woocommerce_connector.job_max_attempts` | 5 | нет | Зарезервировано. |
| `rex_woocommerce_connector.batch_size` | 100 | нет | Зарезервировано; сам клиент API ограничивает пакет 100 объектами. |
| `rex_woocommerce_connector.total_tolerance` | 0.02 | нет | Зарезервировано; используйте поле **Допуск по итоговой сумме** магазина. |

Поведение отдельного магазина настраивается на форме магазина, а не здесь:
**Допуск по итоговой сумме** и **Максимум попыток задания** — поля магазина.

## 21. Страница состояния

Авторизованный пользователь может открыть

```text
https://<ваш odoo>/woocommerce/status
```

Страница возвращает обычный текст с блоком на каждый магазин: состояние
соединения, URL, число заданий в очереди и число заданий с ошибкой. Она
предназначена для быстрой проверки при поддержке и для мониторинга; она никогда не
показывает учётные данные и ничего не записывает.

## 22. Известные ограничения версии 1.0

Это осознанные ограничения первой версии, а не ошибки, о которых надо сообщать:

* **Только Odoo 19.0 и 20.0.** Слой совместимости покрывает эти две версии; более
  старые не поддерживаются.
* **Нет движка сопоставления метаполей.** Дополнительные метаданные WooCommerce не
  импортируются.
* **Строки купонов не импортируются.** Скидка строки сохраняет стоимость купона,
  применённого к товарам; купон на доставку или доплаты делает сумму отличной, и
  это фиксирует проверка суммы.
* **Нет мультивалютных заказов.** Заказ в валюте, отличной от валюты магазина,
  пропускается с ошибкой.
* **Нет комплектов и BoM.** Обрабатываются только простые товары и вариации.
* **Нет подписок, бронирований и POS-плагинов.** Их заказы и дополнительные объекты
  импорт не понимает.
* **Один склад на магазин.** Остатки читаются из локации склада поля *Склад* и
  записываются туда же.
* **Сложные (compound) налоги не сопоставляются.** Строки заказов импортируются с
  суммами без налога и сопоставленными процентными налогами; сложный налог
  WooCommerce может сделать сумму Odoo отличной, и это фиксирует проверка суммы.
  Основная тестируемая конфигурация — цены без налога.
* **Дополнительные плановые действия устанавливаются выключенными.** Экспорт
  товаров, выгрузка запасов, отправка запасов и импорт клиентов включаются вручную,
  потому что они пишут в живую систему или читают весь список клиентов.
* **Возвраты ждут счёта.** Возврат по заказу без счёта импортируется при следующем
  изменении заказа после выставления счёта.
* **Вариации только сопоставляются, не создаются.** Вариация без соответствующей
  вариации Odoo записывается как предупреждение.
* **Нет возврата на склад и сопоставления платежей.** Возврат создаёт кредит-ноту;
  запасы и платежи остаются процессами Odoo.
* **Адрес доставки не является дочерним контактом.** Синхронизируется только
  платёжный адрес.
* **Как статус заказа отправляется только отмена.** Отправка номера отслеживания
  добавляет заметку к заказу; Odoo не отправляет статусы "в обработке" или
  "завершено".

## 23. Устранение неисправностей

| Симптом | Причина и решение |
| --- | --- |
| `401 Unauthorized`, код `woocommerce_rest_cannot_view` | Неверный ключ или секрет потребителя, либо магазин открывается по **обычному HTTP**. WooCommerce 11 аутентифицирует только через SSL: используйте `https://`. В локальном стеке проверьте, что сертификат доверенный, или снимите *Проверять TLS-сертификат* для самоподписанного. |
| `404` с кодом `rest_no_route` | Неверный URL магазина. Это должен быть корень установки WordPress (`https://shop.example.com`), а не страница, не `/shop` и не сам путь `/wp-json/wc/v3`. |
| `Проверить соединение` работает, `Зарегистрировать вебхуки` отказывается | `web.base.url` не является публичным HTTPS-адресом. Задайте его в **Настройки > Технические > Параметры > Системные параметры** и повторите. |
| Вебхук не приходит | Три типичные причины: адрес Odoo недоступен из интернета, cron WordPress выключен (`DISABLE_WP_CRON`) и сайт без трафика, либо вебхуки не были зарегистрированы. Заказы всё равно приходят через опрос каждые 10 минут. |
| `401 invalid signature` в логе вебхуков WordPress | Секрет вебхука в WordPress отличается от **секрета вебхука** магазина — обычно это вебхук, созданный вручную. Удалите его и нажмите **Зарегистрировать вебхуки** ещё раз. |
| Предупреждение `Odoo total … differs from WooCommerce total …` | Ни один налог Odoo не имеет ставки налога WooCommerce, единственный налог Odoo с такой ставкой включён в цену, задействована сложная (compound) ставка, либо купон уменьшил доставку или доплаты. Проверьте **Журнал активности** и карту налогов. |
| `No Odoo sale tax found for rate …` в серверном логе Odoo | Создайте налог продажи с таким процентом для компании магазина, иначе заказ импортируется без него. |
| `The store URL cannot be changed after records have been synchronised` | URL является частью идентичности каждого соответствия. Создайте вторую запись магазина. |
| Задания остаются **В очереди** | Плановое действие очереди неактивно или не работает ни один планировщик Odoo. Включите **WooCommerce: process the synchronisation queue** и проверьте лог Odoo. |
| Задания падают с `WooError` | Прочитайте **Последнюю ошибку** задания и соответствующую строку ошибки в **Журнале активности**: там хранятся HTTP-статус и код ошибки WooCommerce. |
| Изображения не экспортируются | В магазине отсутствуют или неверны *Пользователь WordPress* и *Пароль приложения WordPress*. Об этом говорит предупреждение в журнале; товар всё равно экспортируется. |
| Возврат пропущен | Заказ ещё не импортирован, либо его заказ продажи не имеет проведённого счёта. Оба случая журналируются с причиной. |
| Остатки не отправляются | Источник запасов не **Odoo**, плановое действие выключено (оно выключено после установки) или ни один товар не сопоставлен. Воспользуйтесь **Синхронизировать сейчас**. |

## 24. Политика поддержки

Это общественный проект, поддерживаемый по принципу лучших усилий:

* **платной поддержки нет**, гарантированного времени ответа нет;
* поддерживаемые версии Odoo: **19.0 и 20.0**;
* отчёты об ошибках и pull request'ы приветствуются в трекере;
* указывайте версию коннектора (1.0.0), версию Odoo, версию WooCommerce, шаги
  воспроизведения проблемы и соответствующие строки **Журнала активности** с
  HTTP-статусом и кодом ошибки WooCommerce.

Вопросы о самом Odoo или самом WooCommerce относятся к их каналам поддержки.
